## 1. What this execution closes

Exec 33/34 closed the sale and rental posting paths. Six financial screens still
built their journal in the browser and inserted `journal_entries` /
`journal_lines` directly: **purchases/new**, **cars/new**, **accounting/petty-cash**,
**accounting/bank-transfer**, **hr/payroll**, and **rentals/[id]/refund-deposit**.
The manual **accounting/journal-entries** screen did the same for save, delete and
approve.

Those browser writes bypassed the API auth guard (`requireContext`), derived the
tenant/number client-side, and each carried its own copy of the posting logic.
This execution routes every one of them through a single server-side path that
reuses the already-tested builders in `src/lib/accounting/manual-postings.ts`.

### The rule now enforced

```
page  ->  fetch('/api/...')  ->  route (requireContext + tenant + year + references)
                                    ->  service (builds + writes the journal, idempotent)
                                        ->  journal_entries + journal_lines (canonical)
```

A page may **read** freely; a page may **not** write the ledger, the balance
cache or a document number. Those moved to the server.
