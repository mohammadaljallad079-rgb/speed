## 4. Depreciation and loan repayment (Phase 3) — audited, blocked on policy

### Depreciation

- **Current flow:** `src/app/accounting/depreciation/page.tsx` reads
  `cars.purchase_price/purchase_date`, computes straight-line / reducing-balance, and
  **inserts a `depreciation_schedules` row** (`handleSave`). There is **no** journal
  entry and **no** re-usable posting path (`src/lib/accounting/` has
  vehicle/sales/receipt/payment/purchase/manual postings — none for depreciation).
- **Accounts required:** `ACCOUNT_CODES` across all modules define only:
  `11001/11002/11003` cash/bank/petty, `12001` AR, `21001` payable, `22001` bank loan,
  `24000` VAT, `25000` deposit liability, `13001` fleet, `41001/41002` revenue,
  `51001–51006/51099` expenses, `51003` salaries. **No depreciation-expense account
  and no accumulated-depreciation account exist** in code, and the live chart (per
  Exec 05.x) has no such code either.
- **Decision:** the accounting policy is **not defined** in the project. Per the
  instruction ("if the accounts or policy are not specified, do not invent them"),
  **no posting was implemented.** Required decisions: the depreciation-expense
  account, the accumulated-depreciation (contra-asset) account, the monthly
  frequency, and the start convention (from `start_date`).

### Loan repayment

- **Current flow:** loans are created by `POST /api/cars` (admin, best-effort):
  it inserts `car_loans` and generates the full amortization schedule into
  `car_loan_installments` (splitting `interestPortion = balance * monthlyRate` vs
  `principalPortion`). The purchase journal (`buildVehiclePurchaseJournal`) credits
  `22001` (bank loan) for the financed amount.
- **Gap:** there is **no installment-payment flow** — nothing marks an installment
  paid, and nothing posts `Dr 22001 / Dr <interest expense> / Cr 11001-11002`. The
  UI (`/loans`) is read-only and `/loans/new` does not exist.
- **Decision:** posting an installment requires an **interest-expense account** that
  does not exist, plus a policy on late fees and whether repayment is cash or bank.
  Per the instruction, **no posting was implemented.** The split logic already
  generated at loan creation is a sound basis for a future posting but is not itself
  a posting.

**Both items remain open pending accounting decisions (§12).** No production data was
used.
